## Constitution
Non-negotiable rules for this app's visual identity.
- **Trip-dreaming software, not a data dashboard** (BRIEF §3.6). Default to motion, warmth,
  and photography over dense tabular chrome. When in doubt, choose the more evocative
  option.
- **The map is the permanent full-viewport canvas.** All UI chrome (cards, panels,
  controls) floats above it with soft elevation — never an opaque full-width header or
  sidebar that boxes the map in.
- **Day-marker dots are the app's signature visual language.** Every drive leg and every
  recommended park stay renders dots, always paired with — never replaced by — the numeric
  count ("●●● 3 days"). Dots read first; the number confirms.
- **Never use color alone to distinguish drivable vs. not-drivable parks** (WCAG 1.4.1).
  Pair the not-drivable fill with a distinct stroke ring and an icon glyph.
- **All floating cards/panels use the Radius & Elevation Tokens below** — no ad hoc
  `box-shadow` or corner-radius values anywhere in the app.
- **Respect `prefers-reduced-motion`.** Every Motion Token below collapses to near-instant
  when the OS requests reduced motion. The app must stay fully usable and legible with all
  animation removed — day-dot counts and route/stay information must never depend on an
  animation actually playing to be readable.
- **Display font (Fraunces) is used narrowly** — park name headline, trip/itinerary title,
  and the empty-state hero headline only. Every other heading (section labels, card
  titles, subheadings) uses Inter at a heavier weight. This is a deliberate restraint
  decision: a rare display font reads as intentional; a display font used everywhere reads
  as decoration and dilutes the one moment (a park's name) it should dominate.
- **Numeric/tabular content** (drive hours, day counts in the itinerary table) uses the
  mono token for figure alignment — never the display or body font for numerals in a
  tabular context.
- **Icons from `lucide-react`** — no inline SVG, except the app's own MapLibre marker/dot
  graphics (necessarily custom; see Map & Marker Tokens).
- **UI chrome is built on Shadcn/ui primitives**, restyled via the tokens in this
  document — no ad hoc component libraries.
- **Park photography is a primary visual element**, not decoration. Every park detail card
  shows at least one NPS public-domain photo before descriptive text; never ship a
  text-only park card when an NPS image is available.
- **Minimum touch target 44×44px** for every interactive element, including a map
  marker's tappable hit-area (the visual marker may render smaller; the hit-area padding
  must still reach 44px on touch devices). This app will be previewed on phones — treat it
  as a mobile-first constraint, not an afterthought.
- **Tokens assume a light, warm basemap.** The MapLibre basemap is specified as a free
  outdoorsy/terrain-leaning vector style (light, not dark). Every surface/text token below
  is tuned for that assumption. If P2 research selects a dark basemap instead, this file's
  Color Tokens and Map & Marker Tokens must be revisited explicitly — never silently
  overridden per-component.

## Layout Breakpoints
Reuses Tailwind's default breakpoints so tokens map 1:1 to `sm:`/`md:`/`lg:`/`xl:` utilities.

| Breakpoint | Width |
|---|---|
| `sm` | `640px` |
| `md` | `768px` |
| `lg` | `1024px` |
| `xl` | `1280px` |
| `2xl` | `1536px` |

**Mobile-width behavior (this app will be previewed on phones — non-optional):**
- The full-viewport map remains the base layer at every breakpoint — never replaced by a
  static image or disabled below `md`.
- Below `md` (768px), the floating park-detail card converts from a right-docked floating
  panel to a bottom sheet (Shadcn-style drawer) anchored to the viewport bottom edge,
  draggable/swipeable. It defaults to a "peek" height (name + drive-day dots visible) and
  expands to full detail on tap or drag.
- The itinerary panel becomes a full-screen overlay below `md` (reached via a floating
  action button), not a persistent side panel.
- The dot legend collapses to a single tappable info-glyph chip below `sm` (640px) instead
  of the persistent inline legend shown at desktop widths, to preserve map real estate.
- Map-marker hit-areas keep their 44×44px minimum at every breakpoint; this matters most
  below `md`, where tapping is the primary input.
- Display-font headline steps (`4xl`/`5xl`) drop one type-scale step below `sm` to prevent
  long park names (e.g. "Great Sand Dunes", "Wrangell–St. Elias") from wrapping awkwardly
  on narrow viewports.

## Radius & Elevation Tokens
Floating cards over a live map are the app's core visual language — locking these down
prevents ad hoc shadow/radius values from FE (Constitution forbids that anyway).

| Token | Value | Usage |
|---|---|---|
| `--radius-sm` | `8px` | Small controls, badges, chips, input fields |
| `--radius-md` | `12px` | Buttons, dot-legend chip, tooltips |
| `--radius-lg` | `16px` | Primary floating cards — park detail card, itinerary panel |
| `--radius-xl` | `24px` | Hero surfaces, mobile bottom-sheet top corners |
| `--radius-full` | `9999px` | Pills, marker halos, avatar-style icons |
| `--elevation-1` | `0 1px 2px rgba(42,36,32,0.08), 0 2px 6px rgba(42,36,32,0.10)` | Resting floating card |
| `--elevation-2` | `0 4px 10px rgba(42,36,32,0.14), 0 2px 4px rgba(42,36,32,0.08)` | Hover/raised card, dragged bottom sheet |
| `--elevation-3` | `0 12px 28px rgba(42,36,32,0.18), 0 4px 8px rgba(42,36,32,0.10)` | Selected-park card, modal, popover |

Shadow color is tinted from `--color-text` (warm charcoal) rather than neutral black, so
elevation itself reads as warm/on-brand rather than a generic UI-kit gray shadow.

## Motion Tokens
`App Type: standard` does not template-require this section (Motion Tokens are formally a
dashboard-only section), but BRIEF §3.6 makes animation a first-class product requirement —
"visually appealing and animated FIRST." These tokens exist so FE never has to invent
duration/easing values for the app's signature interactions.

| Token | Value | Notes |
|---|---|---|
| `--motion-flyto-duration` | `1400ms` | Map camera fly-to on park/route selection — long enough to read as a deliberate "journey" beat, short enough not to feel sluggish |
| `--motion-flyto-curve` | `cubic-bezier(0.25, 0.1, 0.25, 1)` | Smooth ease-in-out; matches MapLibre's default `flyTo` easing character |
| `--motion-route-trace-duration` | `900ms` | Animated line-draw duration for a route path |
| `--motion-route-trace-curve` | `cubic-bezier(0.4, 0, 0.2, 1)` | Decisive, smooth trace — not springy (a route is informational, not playful) |
| `--motion-dot-stagger-delay` | `90ms` | Per-dot delay when day-marker dots animate in sequentially |
| `--motion-dot-enter-duration` | `220ms` | Single dot's own scale/opacity-in animation |
| `--motion-dot-enter-curve` | `cubic-bezier(0.34, 1.56, 0.64, 1)` | Springy overshoot — dots should feel tactile/"pop," distinct from the smoother card/route motion |
| `--motion-card-enter-duration` | `320ms` | Popup/info-card enter (photo + description card sliding + fading in) |
| `--motion-card-exit-duration` | `200ms` | Card exit — faster than enter (standard convention: exits should feel quicker, not demand attention) |
| `--motion-card-curve` | `cubic-bezier(0.16, 1, 0.3, 1)` | Confident deceleration, no bounce — cards are informational |
| `--motion-reduced-motion-override` | `≤10ms, no stagger, linear curve` | Applied to every token above when `prefers-reduced-motion: reduce` is set. Dot counts and card content must remain fully legible with this override active. |

## Map & Marker Tokens

### Park Markers
| Token | Value | Notes |
|---|---|---|
| `--marker-size-default` | `16px` diameter | Unselected drivable park marker |
| `--marker-size-selected` | `24px` diameter | Selected marker grows — supports bold visual hierarchy |
| `--marker-color-drivable` | `var(--color-primary)` `#1F4E3D` | Default fill, drivable, unselected |
| `--marker-color-drivable-hover` | `var(--color-primary-hover)` `#163A2D` | Hover/focus fill |
| `--marker-color-selected` | `var(--color-secondary)` `#A83F1E` | Selected marker fill — rust draws immediate attention against the resting pine green field |
| `--marker-color-not-drivable` | `var(--color-not-drivable)` `#A79B8C` | Fill only — always paired with the stroke + glyph below |
| `--marker-stroke-not-drivable` | `1.5px` ring, `var(--color-text-muted)` `#6B6055` | Plus a small "unreachable" glyph (e.g. lucide `signpost-off`) rendered inside the marker at zoom levels where it's legible — shape/icon cue, never color alone |
| `--marker-stroke-default` | `2px` halo, `var(--color-surface-elevated)` `#FFFDF8` | Guarantees marker contrast against an arbitrary basemap terrain color, independent of fill hue |
| `--marker-stroke-selected` | `3px` halo, `var(--color-surface-elevated)` `#FFFDF8` + `--elevation-2` | Elevation cue matching the floating-card language |
| `--marker-focus-ring` | `2px` outline, `var(--color-accent-dusk)` `#4B4368`, `2px` offset | Visible keyboard-focus indicator — chosen because dusk is distinct from both marker greens and rust, so focus never blends into resting/selected states |

**States:**
- *Default (drivable):* `--marker-color-drivable` fill, `--marker-size-default`, `--marker-stroke-default` halo.
- *Hover/focus (drivable):* fill → `--marker-color-drivable-hover`, scale 1.08×, `--marker-focus-ring` visible on keyboard focus, cursor pointer.
- *Selected:* fill → `--marker-color-selected`, size → `--marker-size-selected`, `--marker-stroke-selected`, stay-day dots animate in above the marker (see below), camera flies to it (`--motion-flyto-*`).
- *Not-drivable (default):* `--marker-color-not-drivable` fill, `--marker-stroke-not-drivable` ring + glyph, cursor default. Still clickable to open the info popup (name/description/photos) — just excluded from routing and from "add to trip."
- *Not-drivable (hover):* scale 1.05× only, no color change — communicates "inspectable but inert for routing" without implying it can be selected for a trip.

### Day-Marker Dots
The app's signature visual language — "dots are the at-a-glance language of the app"
(BRIEF §3). One dot per drive day on a highlighted route; one dot per recommended stay day
on a highlighted park.

| Token | Value | Notes |
|---|---|---|
| `--dot-size-sm` | `8px` | Stay-day dots rendered directly on/adjacent to a park marker |
| `--dot-size-md` | `10px` | Drive-day dots rendered along a route line |
| `--dot-size-lg` | `14px` | Dots shown inside the itinerary panel's day rows (larger, isolated UI-panel context) |
| `--dot-gap` | `var(--space-2)` `8px` | Gap between adjacent dots in a cluster/row |
| `--dot-color-drive` | `var(--color-accent-rust)` `#C1502E` | Drive-day dot fill |
| `--dot-color-stay` | `var(--color-accent-dusk)` `#4B4368` | Stay-day dot fill — deliberately a different hue family from drive dots so the two meanings are never confused at a glance |
| `--dot-stroke-color` | `var(--color-surface-elevated)` `#FFFDF8` | Halo/stroke on every map-canvas dot — same rationale as marker halos: guarantees contrast against an unpredictable basemap |
| `--dot-stroke-width` | `2px` | |
| `--dot-max-inline-count` | `5` | Above 5, collapse to a compact pill showing "N days" text instead of rendering individual dots — prevents an 8-day drive leg from becoming visual clutter while keeping the "at a glance" promise |

**States:**
- *Default:* fully filled, static, halo applied.
- *Animating-in:* staggered pop-in per `--motion-dot-stagger-delay` / `--motion-dot-enter-duration` / `--motion-dot-enter-curve`, triggered when a route or park becomes selected/highlighted.
- *Hover (on the parent route or marker):* dots scale 1.1× using `--motion-dot-enter-curve`.
- *Selected:* dots persist filled, halo widens slightly (matches `--marker-stroke-selected` treatment) to signal "this is the active route/stay."
- *Dimmed (backgrounded):* when a trip chain has multiple legs and one is active, dots belonging to non-active legs render at 40% opacity — supports comparing a multi-park trip without visual competition.
- *Reduced motion:* dots appear at final state immediately (no stagger, no pop), per `--motion-reduced-motion-override`.

## Component Rules
Named decisions for recurring component choices:

| Component | Rule |
|-----------|------|
| Primary button (e.g. "Fly to park", "Build itinerary") | Shadcn `<Button variant="default">`, filled `--color-primary` |
| Secondary button (e.g. "Add to trip", "Add nearby park") | Shadcn `<Button variant="secondary">` restyled to `--color-secondary` fill with `--color-text-inverse` label — never `--color-accent-rust` as a button fill (fails AA text contrast) |
| Destructive action (e.g. "Remove park from trip") | Shadcn `<Button variant="destructive">` mapped to `--color-error`, always paired with a confirmation step |
| Ghost/icon button (map zoom controls, close popup) | Shadcn `<Button variant="ghost" size="icon">`, 44×44px hit area |
| Text input (park search) | Shadcn `<Input>` + `<Label>` — never a raw `<input>` |
| Floating info card (park detail popup) | Shadcn `<Card>` — `--radius-lg`, `--elevation-1` resting / `--elevation-3` when active, `--color-surface` background, never a custom `box-shadow` |
| Itinerary panel | Shadcn `<Card>` container + Shadcn `<ScrollArea>` for the day-by-day list |
| Nearby-park suggestion chip | Shadcn `<Badge variant="outline">`, restyled, clickable, `--radius-full` |
| Dot-meaning tooltip ("drive day" vs. "stay day") | Shadcn `<Tooltip>` |
| Loading state | Shadcn `<Skeleton>` for park-detail card content while NPS photo/description loads; a themed pulsing pine-dot triad (custom, `--dot-color-drive`/`--dot-color-stay` alternating) for the map's own "computing route" state — Shadcn has no map-loading primitive |
| Empty state | Icon (`lucide-react`) + heading + body text + CTA — all four required. E.g. `map-pin-off` icon + "Where to next?" (`5xl`, Fraunces) + "Click any pine-green marker to start planning." + implicit CTA (the map itself) |
| Error state | Shadcn `<Alert variant="destructive">` — e.g. NPS API fetch failure, missing drive-time data |
| Dot legend | Custom component (no Shadcn primitive) — persistent key showing drive-dot vs. stay-dot meaning, pinned bottom-left on desktop, collapses to a tap-to-reveal chip below `sm` |
| Map marker / day-dot | Custom SVG components rendered via the MapLibre GL marker layer — not a Shadcn primitive; governed entirely by Map & Marker Tokens above |

## Design Integrity Notes
- **Palette rationale.** WPA-poster warmth (pine/rust/dusk/sand) was chosen deliberately
  over a cooler "tech dashboard" blue/gray palette to reinforce the product's own framing —
  BRIEF §3.6 explicitly asks for the app to feel like trip-dreaming software, not a data
  dashboard. Preserve this triad; resist adding a fourth saturated hue without retiring one
  first (restraint is the point, not a limitation).
- **Two-tier rust exists only for accessibility, not taste.** `--color-secondary` (button-
  safe, `#A83F1E`) and `--color-accent-rust` (decorative, `#C1502E`) are the same family at
  different luminance because the brighter rust fails 4.5:1 with light text on top (4.27:1
  measured). Do not use `--color-accent-rust` as a filled-button background with text.
- **The halo/stroke pattern on every map-canvas dot and marker is load-bearing, not
  decorative.** Contrast against a live vector basemap cannot be guaranteed by fill color
  alone since the basemap terrain varies under the marker. Preserve the halo on every
  future marker/dot variant rather than relying on the fill hue's contrast against a fixed
  background.
- **Fraunces + Inter pairing.** Both are free, variable Google Fonts (single network
  request covers the full weight range each). Fraunces is intentionally rationed (park
  name, trip title, hero headline only) — do not let a future sprint add it "just for this
  one card title too"; that dilutes the one moment it's meant to dominate.
- **`--color-not-drivable` is deliberately not text-safe.** It was designed for a
  low-saturation map-marker fill, not for UI chrome. If a future sprint wants a "not
  drivable" label in a list or table (not on the map canvas), use `--color-text-muted` for
  the label text and reserve `--color-not-drivable` for the marker fill only.
- **Init-mode origin.** This is the project's first DESIGN.md — no prior version, no code
  to infer tokens from (project was greenfield at authoring time, P1 data-foundation
  phase). Expect P2 (Map MVP) to be the first real stress-test of the Map & Marker Tokens
  section in particular; run a visual audit after that sprint and update this file's
  version (PATCH for clarifications, MINOR for new tokens) rather than letting FE drift
  from it silently.
